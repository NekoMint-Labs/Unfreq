## 1. 先区分三个动作

- **撤回公开**：作者停止一条表达继续对其他用户公开。它不等于删除原文、删除音频、删除审计或注销身份。
- **后台隐藏**：管理员限制公开，作者不能靠再次发布绕过处理。
- **彻底删除/注销**：涉及原文、派生内容、媒体、审计、他人互动、身份关联和历史备份。本轮不执行，不预设保留天数、硬删除范围或注销规则。

推荐本轮最小范围：确定撤回后的访问和再发布规则，建立全入口可见性约束；不增加物理清理任务、不批量删历史记录。任何具体删除、保留期和备份处置策略以后单独提交设计。

## 2. 当前状态与读取事实

`signals.status` 只有 `DRAFT/PUBLISHED/REVIEWING/HIDDEN/DELETED`；**没有独立的已撤回状态或作者撤回端点**。`generation_status` 为 `RECEIVED/EXPANDING/MATCHING/WRITING/COMPLETED/FAILED`，与公开状态是两个维度；音频另有 `NOT_REQUESTED/PENDING/READY/FAILED`。

下表描述普通信号详情 `GET /api/signals/:id`；管理员列指受鉴权的后台接口，不意味着管理员能通过普通详情 URL 绕过过滤。作者发布的 409 / 404 结果以有效且 ACTIVE 的作者会话为前提；未登录和非 ACTIVE 身份会先被拒绝。

| 当前状态组合 | 作者详情 | 匿名/其他用户详情 | Galaxy/Hall/随机/候选匹配/回声/音频 | 本人历史与后台 |
|---|---|---|---|---|
| 非 COMPLETED 且非 DELETED，包括生成中及 FAILED | 200，`GENERATION_OWNER`，原句、进度或安全失败提示 | 404 | 不公开，不能发布；发布返回 409 | `/me/signals` 当前不列未完成记录；后台可查看 |
| COMPLETED + DRAFT | 200，`PREVIEW_OWNER`，私密预览正文 | 404 | 不公开；ACTIVE 作者确认发布可转 PUBLISHED | 本人历史包含；后台包含 |
| COMPLETED + REVIEWING | 200，完整作者结果 | 200，仅 `id/status/createdAt/updatedAt/visibility=REVIEW_RESTRICTED` | 不进入公开集合，不能发布；作者发布返回 409 | 本人历史及后台包含 |
| COMPLETED + PUBLISHED | 200，公开详情 | 200，含 rawInput、seedText、expandedText、fingerprint、frequencyProfile、program 等当前公开字段 | 可公开读取；互动写入仍需合法身份及目标可见 | 本人历史及后台包含 |
| COMPLETED + HIDDEN | 404 | 404 | 不公开；作者发布为 404 | **本人 `/me/signals` 当前仍可带出原句和扩写**；后台包含 |
| DELETED，任意生成状态 | 404 | 404 | 不公开 | 本人历史排除；后台仍可查看 DB 中保留的记录 |
| 作者已撤回 | 当前不存在此独立语义 | 当前不存在 | 不能将后台转 DRAFT/HIDDEN 的测试说成已实现作者撤回 | 待本稿确认后由 C1 实现 |

事实边界：详情逻辑先判断生成状态，再判断 HIDDEN。因此“未完成 + HIDDEN”目前仍可能向作者返回 `GENERATION_OWNER`；上表 HIDDEN 行特指已完成。公开集合仍要求 `PUBLISHED + COMPLETED`。后续需统一权限判断优先级，不能根据一张表推断所有异常组合已经一致。

本人 `/api/me/signals` 当前按 authorId 查询最近最多 80 条 COMPLETED 且非 DELETED 的记录，包含 HIDDEN，并返回原句和扩写。其总共振数也是这批记录之和；不能把该数解释为全历史聚合。匿名详情、Hall 和随机读取目前均使用完整详情 DTO，尚未实施第 8 节建议的公开字段最小化；字段存在时还会带出内部 frequencyId 和历史 guestKey，不能只按页面可见文字盘点身份数据。

现有公开写入规则：创建/发布/新增共振/收藏/回声需要有效身份，创建和新增互动还要求 ACTIVE；公开内容被过滤后，新增互动应拒绝。取消收藏当前只按本人和信号 ID 删除收藏关系。BANNED 身份不能恢复为有效会话，MUTED 身份的读取与写入权限不是同一回事。

## 3. 当前写入与持久性事实

| 写入路径 | 当前事实 | 生命周期约束建议 |

## 5. 建议批准的目标权限与状态转换

这里的“已撤回”是待批准的逻辑状态，不预先指定新增 enum 还是独立字段。C1 应选择可回滚、兼容现有 DRAFT/审核状态的最小实现；用户无需替工程代理选择数据库字段。

| 目标状态 | 作者私密读取 | 匿名/其他用户 | 作者公开操作 | 管理员及后台任务 |
|---|---|---|---|---|
| 草稿/生成中/失败 | 本人受控预览或进度；不强行进入公开读取接口 | 正文和派生内容不可读 | 仅 COMPLETED 且允许发布时确认发布 | 可以审核/诊断；任务不能自行公开 |
| 待审核 | 保留本人结果及审核提示 | 暂维持现有无正文的受限状态返回 | 不能绕过审核公开 | 管理员处理；任务完成不能覆盖审核状态 |
| 已发布 | 正常可读 | 只返回经决定 2 批准的公开字段 | 作者可撤回；重复撤回应幂等 | 所有公开输出检查 PUBLISHED+COMPLETED 及失效版本 |
| 已撤回（待批准） | 推荐作者可继续私密查看 | 公开详情、发现、分享与媒体不可读 | 推荐只有作者再次明确确认才可公开，且审核/隐藏/账号限制仍优先 | 后台可受控查看；旧任务不能重新公开或清除撤回标识 |
| 后台隐藏 | 后续统一受限提示与本人历史口径；本轮不把它自动变成作者可发布草稿 | 不公开 | 作者不得自行恢复公开 | 仅合法管理员解除；需保留处理记录 |
| 逻辑删除 | 暂保持现有普通读取不可达 | 不公开 | 不允许恢复发布 | 不能被旧任务重建为 DRAFT/PUBLISHED；仍不是批准物理清理 |

下面是目标转换表，不是现有数据库 enum 或已实现 API：

| 起点 → 终点 | 发起者与必要条件 | 必须保留的约束 |
|---|---|---|
| 创建 → DRAFT + RECEIVED | 合法 ACTIVE 作者，创建输入通过验证 | 不因后台开始生成而公开；持久生成请求只保存恢复所需上下文 |
| 生成中 → COMPLETED / FAILED | B1/B2 定义的当前有效 attempt，合法生成状态迁移 | 只写自己的生成结果；不清除审核、隐藏、撤回或删除状态；耗尽重试进入可解释终态 |
| COMPLETED + DRAFT → PUBLISHED | ACTIVE 作者明确确认；没有审核限制 | 发布和权限检查在同一条件更新中成立；不能由定时扫描或 AI 完成自动触发 |
| PUBLISHED → 逻辑已撤回 | 作者撤回；确切接口和持久表示由 C1 定义 | 不物理删除；撤回与生成 attempt / 公开版本的栅栏一起提交；重复操作幂等 |
| 逻辑已撤回 → PUBLISHED | 仅当决定 1 批准再发布，ACTIVE 作者重新确认 | 已完成且无审核限制；不清除举报 / 审计，不自动恢复公开 |
| 允许的非删除状态 → REVIEWING / HIDDEN | 合法管理员按既有审核职责处理 | 保留操作记录，作者不能借撤回或再发布绕过限制 |
| REVIEWING / HIDDEN → 管理员明确选择的状态 | 合法管理员解除限制 | 不把“解除审核”默认为替作者同意公开；具体恢复语义由实施 PR 复核 |
| 允许状态 → 逻辑 DELETED | 合法管理员按既有权限处理 | 不能被旧任务重建或重新发布；本动作不等于物理擦除 |
| 任何状态 → 物理删除 / 身份注销 | 本轮未授权、无实施入口 | 等保留范围、备份和恢复方案独立批准；不在撤回 PR 中加入清理 |

既有 schema 的状态与生成阶段仍为第 2 节两组枚举。B1/B2 可以先为既有 DRAFT / REVIEWING / HIDDEN / DELETED 建立 attempt 栅栏；作者撤回部分须等决定 1 和 C1 契约确定后补齐，不能提前宣称完整验收。

## 6. 撤回后的强不变量

1. **源站公开读取**：撤回事务提交后发起的新公开请求或缓存回源，不能得到该信号的原句、正文、指纹、向量派生摘要、音频或分享预览。统一覆盖详情、Galaxy 点线、Hall、随机、匹配候选及结果、回声父对象、收藏、OG、Web SSR/metadata 和关联音频 URL。独立上传图片当前没有 signalId 关联，另待关联与授权设计，不能承诺其随信号自动失效。
2. **系统复制内容**：其他公开信号中的 `program.rightSignalSummary` 等受控副本，也必须依据原对象可见性停止返回；仅使原 URL 404 不足以完成验收。用户自己的续写作为独立作品处理，不承诺自动撤销所有人工引用。
3. **晚到任务与并发**：生成、向量/位置补写、TTS、重试、管理员变更都不能使旧 attempt 覆盖撤回/审核/删除。使用条件更新或版本栅栏；发布/撤回/隐藏竞争的最终状态及响应应可解释。
4. **私密与后台权限**：作者读取不进入公图或候选；其他人不能借猜测 UUID、改 cookie、缓存或后台接口取得内容。管理员是有审计的受控角色，不等于内容已对公众开放。
5. **派生统计**：公开集合/统计排除撤回对象；本人历史可保留并标注状态，不能把样本量说成全历史。收藏关系可保留，但不能继续返回目标正文。月度回顾须标生成时点，不能冒充实时公开总量。
6. **缓存承诺准确**：音频/图片当前一年 `public,immutable`，OG 为 300 秒 + 86400 秒 SWR。关联音频和 OG 的旧缓存与即时撤回存在冲突，C1/F2 必须处理受控缓存及后续缓存指令；独立图片保留第 4 节的关联边界。不能追溯清除第三方缓存、已经下载文件或已发出的网络响应。对在途公开响应增加终态检查/失效栅栏，清楚记录无法追溯收回的边界。
7. **恢复不会复活公开**：隔离恢复后先核对有效撤回/审核/删除状态，再开放读取。若只有旧快照而缺少较新状态依据，默认不得自动重放旧公开状态。

推荐界面提示草案：**“撤回后，这条表达将不再通过平台公开展示。你仍可私密查看（以决定 1 为准）。已经被他人下载或第三方缓存的副本，平台无法保证立即清除。撤回不等于彻底删除。”** 此提示不能代替后端验收。

缓存证据：`apps/api/src/modules/signals/routes.ts:146`；`images/routes.ts:52`；`apps/api/src/shared/response.ts:26`；`apps/web/src/app/api/og/[signalId]/route.tsx:32,186`；`apps/web/src/lib/signal-data.ts:237`；`apps/web/public/sw.js:6,33`。私密响应建议明确 `Cache-Control: no-store`；可撤回的公开产物使用可重验证策略，不在 A3 凭空规定新的缓存秒数。

## 7. 可执行验收清单（全部为设计目标，未在 A3 执行）

仅用隔离 PG/Redis、本地 Provider 桩和合成表达；沿用 A2 的真实 Fastify 链，不接生产或付费 Provider。作者撤回端点名称/契约由 C1 确定，下面不杜撰现有路由。

- **L01 状态×身份**：建作者 A、其他用户 B、管理员 C 和匿名访问者；覆盖生成中、FAILED、DRAFT、REVIEWING、PUBLISHED、逻辑已撤回、HIDDEN、DELETED，另建 PUBLISHED+未完成异常组合。第 2 节只记录修复前观察值；实施后的期望按第 5 节获批矩阵验证，不能要求相互冲突的新旧行为同时成立。REVIEW_RESTRICTED 可 200，但必须精确无正文。
- **L02 撤回权限与幂等**：A 撤回成功；匿名拒绝；B 不能撤回 A 的对象，推荐沿用现有作者发布的 404 隐藏存在性契约；重复撤回不创建媒体/收费任务、不改变其他对象。A 不能借撤回/再发布绕过后台限制。
- **L03 全读取面**：撤回前证明公开对象真实可读并被收藏/匹配；撤回后复测 `GET /api/signals/:id`、`GET /api/signals/hall`、`GET /api/signals/random`、`GET /api/signals/galaxy`、`GET /api/signals/:id/matches`、`GET /api/signals/:id/echoes`、`GET /api/me/saves`，以及同一数据的 Web 结果页、metadata、OG。检查集合成员、连线、摘要和正文，而非只断言 HTTP 状态。
- **L04 系统副本反例**：先让公开 B 的 `program.rightSignalSummary` 引用 A；A 撤回后，B 的公共详情、Hall 与分享产物不得再返回该系统复制摘要/链接。保留 B 自己的独立正文，不批量删除续写。
- **L05 已有音频**：写真实合成音频字节，确认公开时 metadata 和 main/left/right 文件读取成功；撤回后即使文件仍在，也要拒绝全部下载和 POST 新生成入口。单独记录旧浏览器/第三方缓存无法保证即时擦除。
- **L06 晚到与竞争**：分别挂起生成、TTS、Embedding 回写；撤回/隐藏/删除后释放任务；旧任务不得恢复公开。生成撤回场景采用合法序列：旧 attempt 挂起 / 过期，较新 attempt 完成，作者发布再撤回，最后释放旧 attempt；不假设未完成草稿已有撤回入口。交错发布/撤回/管理员处理、多次重试的最终状态满足版本条件，不能仅凭顺序执行通过。
- **L07 私密与统计**：按决定 1 检查作者私密入口及再发布；其他用户收藏不返回原文；公开点数/列表排除对象；本人统计和历史快照注明口径。重新发布不会清掉既有举报/审核。
- **L08 缓存与响应**：记录私密/公开详情、OG、音频的真实响应头；模拟源站新请求、受控缓存回源及已有在途任务。把“服务器已拒读”“自控缓存已失效”“第三方旧副本不可控”分别报告，不能合并成一项通过。
- **L09 副本追溯**：对一条带唯一合成标记的表达，列出 signals、相关 program 副本、向量、审计、互动、音频、日志和 SQL 快照的存在/可见/失效状态；审计没有 target 的记录须说明无法自动完整关联，不能伪造删除完毕。
- **L10 恢复与零物理清理**：仅在隔离环境从旧快照恢复，确认未完成状态核对前外部公开入口关闭；记录 DB、媒体、扩展、配置与密钥的恢复缺口。本轮只做设计，不实际运行恢复、清理或硬删除，不填写虚构 RPO/RTO。

执行时由每个实施 PR 补命令、真实结果、未运行项及证据路径。现有 A2 的公开过滤测试只是基线，不能自动折算成“作者撤回已完成”。

## 8. 仅需所有者确认的两个决定

### 决定 1：撤回以后，作者还能怎样使用这条表达？

**推荐最小方案**：可私密查看；保留已有互动关系和历史计数；允许作者再次主动确认发布同一条记录，但仍受账号状态、审核、后台隐藏/删除限制。撤回期间不公开，也不自动恢复；再发布不清除举报/审计。

备选：可私密查看，但本轮不开放再发布。两者都不包含彻底删除、注销或批准具体保留期。

### 决定 2：作者点击发布时，究竟同意公开哪些内容？

**当前事实**：公共详情 DTO 会返回原始 `seedText/rawInput`、扩写、FM/频率标识、详细 `fingerprint` 和节目摘要；不能把“匿名”解释成“原句与 AI 推断一直私密”。

**推荐方案**：公开用户确认的扩写正文、FM 和发现需要的最少标签；原始 Seed/rawInput 与详细 AI 推断默认留在作者私密视图。发布确认应明确列出将公开字段。这会改变现有公共 DTO/页面，需要单独、兼容地实施。

兼容备选：继续公开原句与扩写，但在预览中准确展示公开范围，并审查是否有必要暴露完整推断和内部频率 UUID。**未确认前不修改现有字段，也不扩大发布范围。**

两项决定均为**待确认**。批准时记录答复、日期、选定公开字段及受影响契约，再把目标矩阵转为实施依据。本轮不追加保留天数、硬删除、注销、备份销毁或第三方删除承诺的决定；这些留待后续独立设计。

## 9. 身份与第三方处理说明草案

以下文字依据当前代码撰写，尚未部署到产品页面，也未完成第三方协议和实际生产配置核查。发布字段与撤回部分须在决定 1 / 2 和对应实现验收后替换为已确认规则。

### 当前处理的说明

你在 Unfreq 中以 FM 代号展示身份。使用邮箱验证时，服务端会处理邮箱和验证码挑战；使用密码登录时会校验保存的密码哈希。服务端仍通过内部账号标识关联表达、收藏、共振和审核记录，所以 FM 匿名展示不意味着这些记录之间没有关联。

发射一句 Seed 后，服务端会保存输入，并根据实际启用的服务完成扩写、情绪指纹和匹配。Chat 服务可能收到输入及任务所需上下文；启用向量服务、重排或朗读时，相关文本还可能发送给 Embedding、Reranker 或 TTS 服务。重排输入可能同时包含待匹配表达和候选表达。部分处理发生在你确认公开之前。AI 生成的情绪描述不等于心理诊断。

现有公开详情会包含原始输入、扩写和较完整的分析字段。公开范围正在按本稿第 8 节确认；确认前，不能告诉使用者“原句始终只有自己可见”。第三方的具体名称、处理位置、保留时间、训练用途和删除机制需要按最终服务配置及协议核查，本稿未作承诺。

### 撤回功能验收后可采用的提示

“撤回后，这条表达将不再通过平台公开展示。你仍可私密查看，是否可以重新发布以当时确认的规则为准。平台无法保证立即清除他人已经下载或第三方缓存的副本。撤回不等于彻底删除，备份与第三方已接收的数据也需要分别处理。”

### 实施分工与恢复边界

B1/B2 负责持久任务、attempt 和晚到写入；C1 负责撤回和公开入口；B3 负责验证码与受限诊断；F2 负责数据副本、日志、媒体和隔离恢复演练。身份镜像和实际 Provider 血缘分别由 F1 / E1 补齐。

恢复演练只能在明确隔离的合成环境执行。SQL dump、媒体文件、Redis 持久化、扩展、配置与密钥是不同对象；仅恢复 PostgreSQL 不能宣称完整恢复。没有较新的撤回 / 审核状态依据时，不应把旧 PUBLISHED 数据直接重新公开。RPO / RTO 和第三方处理事实在实际核验前均标记未验证。

现有恢复脚本没有 `ON_ERROR_STOP`、原子事务或隔离开放门禁，并会在命令流程结束后打印恢复完成；这条日志不能单独证明每条 SQL 均成功或生命周期状态已复核。F2 需在合成恢复实验中验证失败退出、部分恢复处理及开放条件。本稿没有执行原恢复命令。
