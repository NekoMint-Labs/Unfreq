## 修改

- `scripts/api-entrypoint.sh` 固定 LF 换行，`.gitattributes` 保证后续 Windows 检出仍保留 LF。原主目录文件实际含 CRLF，Linux 直接执行 shebang 有失败风险。迁移成功后进入 API 工作目录并 `exec node dist/server.js`，使应用接收容器 PID 1 的 SIGTERM；迁移失败仍立即退出。
- `Dockerfile.api` 增加 `NODE_IMAGE` 参数，默认仍为 `node:22-alpine`。验证入口将三个基础阶段固定到同一官方 digest，保留原有正常 `npm ci`、postinstall、生产依赖和 TypeScript 构建。
- 新增 `npm run api:image:verify`。冻结 Docker COPY 输入、运行器和探针；使用有内存及并行度限制的临时 builder，顺序构建 deps、prod-deps 和真实 runner。运行阶段使用独立 internal 网络、临时 PG/Redis 和合成账号，无宿主端口、生产卷、实际 `.env` 或 Provider 凭据；四项付费预算均为零。清理只按本轮随机所有权标签处理自有容器、网络、卷和 builder，不做全局 prune。
- 支持 `npm run api:image:verify -- --resume-runtime=<本轮已有runId>`：只恢复仓库证据目录中已成功构建、已释放 builder 的自有镜像；逐项核对相同的 Docker 输入、既有冻结副本、未变的探针/builder、镜像 ID 和所有权标签。运行器本身可以更新，差异明确写入 `buildReference.verifierChanged`。不能指定其他镜像、数据库、项目或任意路径。PG/Redis 优先读回本机已安装镜像的固定 RepoDigest，缺失时才访问 registry；这不是查询最新版本。
- `npm run web:test` 先真实构建 contracts。旧入口在干净的 `contracts/dist` 缺失时仍有与首轮 PR CI 相同的运行导入缺口；此前 `590f8f4` 只补了 CI 的前置步骤。现根目录的独立 `web:test` 和 `web:check` 均沿此入口准备共享运行包。
