# F2 补充：合成 Redis AOF 检查点恢复

日期：2026-11-01。独立命令为 `node scripts/verify-redis-aof.mjs`；只有无参数演练和 `--help`，不接受 Redis URL、Docker 资源名、目录、镜像或现有卷覆盖。原 SQL/媒体恢复及其历史成绩保留；本项不修改生产配置、部署脚本或 A3 数据处置规则。

## 范围

运行器固定 Redis 镜像 digest、Linux amd64 架构和本机 Docker endpoint，每次新建随机带所有权标签的 internal 网络、五个独立数据卷及临时容器，不映射任何宿主端口。每个 client 生命周期仅启动一个 `docker exec -i <拥有的容器> redis-cli -2 --json` 持续会话，无 TTY、宿主 socket 挂载或额外依赖。显式固定 RESP2，避免 --json 自动尝试 RESP3 后 CONFIG GET 从交替数组变为 map；仍逐行输出 JSON，参见 [Redis 7.4 CLI 源码](https://github.com/redis/redis/blob/7.4/src/redis-cli.c)。配置明确为 appendonly=yes、appendfsync=always、aof-load-truncated=no、禁止自动重写且不启用 RDB。该配置为合成验证条件，不表示生产配置已调整或已通过相同持久性验收。

一次性消费与共享预算使用生产源文件中的真实 Lua：`auth/service.ts` 的 verifyChallengeScript，以及 abuse-control.ts 的 redisClock/quotaScript。只读提取已知模板、明确展开 redisClock，拒绝未知插值和转义，不导入应用、环境或数据库模块；记录源码和 Lua SHA256。合成身份、键、挑战摘要与预算不是生产邮箱、验证码、密钥或批准的实际费用配置。没有调用 API 登录、会话签名、PostgreSQL 或 Provider，因此本项不等于完整应用恢复。

## 演练设计

1. 写入合成待消费挑战、带绝对过期时刻的键、已花费一次的共享预算和检查点标记；错误验证码执行真实 Lua，确认 KEEPTTL 未延长原期限。
2. 在同一持续连接上执行 WAITAOF 1 0 5000，明确收到本机 AOF fsync 确认后正常停机，再完整复制 multipart AOF 目录及 manifest。复制前目标必须为空，源与目标逐文件字节数/SHA256 一致。
3. 重启源实例，消费挑战、花完三次合成预算并确认下一次拒绝，写入较新标记及短 TTL 键；再次确认 AOF 检查点、停机，并等待短期限过去后复制当前检查点。
4. 当前检查点在新卷/新实例恢复后，较新标记存在、长 TTL 的绝对过期时刻不变、短 TTL 键消失、已消费挑战不复活，预算仍满且继续拒绝。
5. 单独恢复较旧检查点，实际证明：未过期的旧挑战会重新出现并可再次被真实 Lua 消费，额度也退回旧计数并可再次花费，较新写入缺失。这个反例必须成立，不将任意旧备份写成安全恢复。
6. 再用一个当前检查点副本，仅截断最后一份 incremental AOF 的一个字节，确认只改了该文件。严格 aof-load-truncated=no 的 Redis 必须非零退出并报告 AOF 读取失败；不调用修复工具、不接受自动丢尾恢复为成功。

[Redis WAITAOF 文档](https://redis.io/docs/latest/commands/waitaof/) 明确它针对同一连接先前的写入。持续 redis-cli 会话逐行接收双引号编码的可信 argv，按行解析有界 JSON 响应，命令串行排队。记录写入前、WAITAOF 前及其后的 CLIENT ID，并要求三者相同；不能用每条命令各开一个 redis-cli 连接的空等待冒充持久化屏障。QUIT 必须等实际子进程退出，失败时中断客户端并在拥有容器清理中收敛。[持久化文档](https://redis.io/docs/latest/operate/oss_and_stack/management/persistence/) 说明 AOF 重放与截断行为；本轮不据此推定随机断电、宿主磁盘故障或陈旧备份的零丢失。

## 所有权、证据和清理

所有 Docker 操作使用无 shell 的 argv，外部 Docker endpoint 在创建资源前拒绝，核验本机 context 后固定后续 endpoint。卷不能预先存在；helper 只挂载本轮拥有的卷，复制源只读，不挂载宿主目录。清理先逐个核验生成名、run/scope/kind 标签及容器固定镜像，再删除本轮容器、卷和网络；任何所有权不匹配都拒绝删除并记失败。无全局 prune、现有服务或生产卷操作。

证据写入每次独立的 `test-results/redis-aof/run-<随机>/manifest.json`，包含真实阶段、检查结果、执行码、源文件/AOF 指纹及清理结果；首次失败和后续重跑分开。镜像仅在明确 No such image 时拉取，下载独立上限 300 秒，其余 Docker 操作上限 30 秒；该准备预算不修改 Redis 命令/屏障预算。失败保留允许的固定原因及本脚本行号，不记录任意错误文本、Lua/挑战正文；在清理前保存已拥有 Redis 的有限启动日志和状态。正常失败或信号处理中尝试有界清理；强杀协调器或宿主崩溃不能承诺自动清理完成，需按保留清单核对同一随机标签。
