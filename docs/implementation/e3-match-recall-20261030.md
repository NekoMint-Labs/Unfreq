# E3：召回、接受门槛与来源策略——工程及合成验收

日期：2026-10-30。基线 `0cf4e2f`（E2 同步记录），分支 `codex/e3-match-recall`。用户确认目前没有真实样本与人工相关性标注，本轮先完成代码和合成验证。因此本记录不代表总规范 E3 的真实模型/人评验收已完成；未执行收费调用、真实数据迁移、合并或部署。

## 候选与排序

语义召回和规则召回先合并、按 ID 去重，再用同一个 Provider 完整重排；只有最终展示才取至多三条。规则池不再只看最近 50 条，而在全部合格记录中，按作者已确认的主频段、标签重合数、时间和 ID 确定候选。标签排序只用于候选召回，不进入最终分数；最终仍完全复用 E2 的范围契约、cosine 映射、规则分与 0.6/0.4 权重。

没有向量的规则候选也可进入合并批次，其请求不伪造 cosine 距离。语义生成已有 query 向量时继续复用，即使候选为空或语义查询普通失败，也不为此再调用一次 embedding。模型返回不完整、无效或超时，仍按 E2 整批回退；不把取消、预算拒绝或任务失效当作普通降级。

工程默认值是可配置的暂定值，尚未经过真实样本校准，不能据此批准生产效果：

| 配置 | 默认 | 约束 |
| --- | --- | --- |
| SIGNAL_MATCH_SEMANTIC_CANDIDATES | 12 | 1–50 |
| SIGNAL_MATCH_RULE_CANDIDATES | 24 | 1–50 |
| SIGNAL_MATCH_MIN_SCORE | 80 | 0–100，采用 E2 组合分，不是概率 |
| SIGNAL_MATCH_MAX_RERANK_CHARACTERS | 12000 | 1–100000，按 JS UTF-16 单元计 |

合并批次最多 100 条，默认最多 36 条；在 dispatch 前计算正文总长度，超过预算则整批跳过 rerank，不裁剪、拆批或改写候选。达到接受门槛、分数大于零且仍通过最终公开复核的结果才可展示。门槛未达到时返回空数组，不用弱规则候选补满三条。正常降级仍使用相同门槛；没有可靠模型/向量证据时，只有规则的最高 40 分通常低于暂定 80 分门槛。

数据库返回数量有上界，但 PostgreSQL 的过滤、标签排序及精确向量检索仍可能扫描较多数据；本轮不宣称生产规模性能或索引验收。更大的 K 也增加请求正文量，不等于效果一定更好。

## 作者与来源

当前陌生人匹配只推荐 `source=human`、有已知作者且作者不同的公开表达。这里 human 表示“用户发起”，正文仍可能由 AI 扩写，不表示纯人工创作。系统生成和演示样本不进入这个候选池；其内容与历史公开状态不被删除或改写。

排除被查看表达的作者，以及已认证访问者本人。创建路径使用服务端当前频率 ID，公开详情和 `/matches` 使用服务端父记录/会话身份，不接受客户端声明作者。匿名访问无法识别物理访问者，但仍排除被查看表达的作者。没有已知作者的历史记录不参与该发现策略。

SQL 在 LIMIT 前执行公开、来源和作者约束，避免本人/系统内容占满候选位；读取后仍验证确认快照。合并时发现同一 ID 的公开版本不一致则舍弃。配置加载、模型调用和最后公开投影后都复核，包含来源或作者晚到变化。C1 的审核、撤回、公开版本和私密字段白名单继续生效。

匹配 DTO 追加可选 contentSource，值从当前数据库元数据取得，不能从 PUBLISHED 状态猜作者来源。公开页和匹配卡片使用“用户发起 / 系统 AI 生成 / 演示样本”；旧响应或未知来源显示“来源未标注”。前端严格校验器同步接受且验证 contentSource、E2 scoreProvenance 和 0–100 分数，继续拒绝额外原始分、模型与私密内容字段。

## 冻结样本与指标定义

样本为 `apps/api/tests/fixtures/e3-matches.v1.json`，4 个查询、77 条候选，SHA-256 为 `d4f28b781b89b3a2205099ab84a193dca0fbb430bb7e9d7b76293ddea307b75b`。旁边的 sha256 文件和单测防止静默改题，`.gitattributes` 对这两个文件关闭换行转换；已核对工作区、Git 暂存区及启用自动换行的检出过滤结果，样本哈希一致。它是显式的 `synthetic-presets-not-human`：正文、向量和相关等级均为构造的回归条件，不是自然用户分布，也不是人工相关性标注。

四类用例分别为语义排名第四、近期窗口外且无向量的相关记录、没有合适结果、本人/访问者/AI/演示/隐藏/撤回/未确认混合候选。等级 0–3 为预设标签，只有符合本轮候选资格的记录可被预设为相关。

指标采用明确分母：semantic Recall@K 是语义池覆盖相关标签的比例，pool Recall 是合并后池的覆盖比例；先去重，不重复计算同一 ID。nDCG@3 使用 `DCG = sum((2^grade-1)/log2(rank+1))`，再除以理想排序的 DCG。归一化排序评测的背景见 [Stanford 信息检索教材](https://nlp.stanford.edu/IR-book/html/htmledition/evaluation-of-ranked-retrieval-results-1.html)。没有正相关标签的查询不参与宏平均 Recall/nDCG，单列无匹配率与空真值误匹配率。人评相关性固定为 null，不用合成标签冒充。

对照包括 E2 基线（K=3、近期规则 50、语义先占位）和合并策略的 K=3/12/24、门槛 0/80/95。基线仅存在于隔离测试驱动，复用 E1 输入模板及 E2 适配器和公式，没有把第二套线上评分藏进生产路径。

评测通过真实 Fastify 管理接口配置本地 Provider，实际走 HTTP transport、PostgreSQL/pgvector、确认快照及公开 HTTP 投影。Provider 仅按冻结 ID 返回预设向量/分数，验证的是机制，不是语言模型理解能力。固定 corpusIds 仅为内部评测限制公开候选集合，不是 HTTP 参数，也不能绕过公开、身份或来源过滤。

每次回放记录实际请求次数、请求字节和本地整体耗时，报告 p50/p95；额外 HTTP 投影验证的请求另列 verificationMeters。基线测试适配有记录映射开销，时延不是生产性能对比，样本仅四组也不足以做性能统计。Provider 返回的 token 值是合成数值，货币费用为 null/unknown，不生成实际费用结论。

## 剩余验收与回退
