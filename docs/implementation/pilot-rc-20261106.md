## 给操作者的准备说明

### 隔离启动与复现

在一次性的本地 Linux Docker 主机或 CI runner 上，检出最终 PR 的精确 Head 后执行：

```bash
node scripts/verify-pilot-compose.mjs
```

该命令直接构建仓库的 Dockerfile.api/web，用真实 compose.yaml 启动 Caddy、Web、API、PostgreSQL、Redis。它生成独立 project name、临时配置和随机合成密钥，不读取现有 `.env`；两个网络均限制外连，不发布宿主机端口。所有付费 API key 为空，四类 Provider 额度为零，调度关闭。探针从本次 API 容器经过实际 Caddy 访问 Web/API，检查五服务健康、数据库/Redis、举报回执匿名权限和 25 条迁移，然后清理本次容器、网络、volume 与临时密钥文件；Docker 构建缓存和镜像保留。结果见 test-results/pilot-compose/*/report.json；这不是部署入口。

人工试用使用独立的新目录、新 Compose project、新数据库及媒体 volume。由 `.env.example` 复制配置，替换两个强随机密钥和实际 HTTPS origin；`deploy/demo.env.example` 中的 HTTP localhost 和空密钥不能直接用于 production。配置完整 ABUSE_LIMITS_JSON 后，先运行 `docker compose --env-file <隔离配置> config`。真实入口启动步骤见[部署指南](../deployment.md)；不要把本轮 CI 合成配置直接用于公网服务。本任务只提供和验证候选，不执行目标环境部署。

### API、Web、策略共同升级

API、contracts、Web 必须使用同一候选版本。#27 在公开 match DTO 中增加 contentSource，旧 Web 严格校验器不接受该字段；不能分开升级或回退。#26 要求策略同时包含 reportRequestUser、reportRequestIp、reportReadUser。deploy/abuse-policy.example.json 列出全部 26 项，默认全部为零，表示拒绝。正式非零额度应由操作者按试用规模和预算确定。三份环境模板的真实配置加载回归、缺失举报额度的拒绝回归，以及实际 API 镜像均检查组合策略。

初始隔离验收保持 AI_API_KEY、AI_FAST_API_KEY、EMBEDDING_API_KEY、RERANKER_API_KEY、TTS_API_KEY 为空，并将 chatCallsSite、embeddingCallsSite、rerankerCallsSite、ttsCharactersSite 设为零。新库不导入已有 Provider 配置；恢复旧库时，数据库中的启用配置也必须禁用。不要用“环境变量为空”推断数据库中不存在已保存的 Provider。调用预算计入重试/备用请求，TTS 以 UTF-16 字符计量，不能直接换算成账单金额。没有另行授权时不执行收费调用。

### 代理与 IP 信任

Caddy 的 HTTPS Web upstream 规则由镜像浏览器验收覆盖。API 的 TRUSTED_PROXY_CIDRS 默认留空，忽略来访 X-Forwarded-For；此时代理后的访客共享代理 IP 额度。目标环境需验证真实 NPM → Caddy → API 地址与转发头覆盖，再填写实际代理 CIDR，禁止信任任意客户端、布尔开关或跳数。当前测试不代表公网代理链已验收。详细检查见 [B3 预算与代理边界](b3-pilot-boundaries-20261101.md)。

### 备份、恢复与较新撤回

备份使用 `UNFREQ_BACKUP_FILE=<新的文件名> ./scripts/deployment-stack.sh server backup`；同时私下保管配置、PROVIDER_CONFIG_SECRET、图片/音频 volume 和恢复所需的会话状态。备份仅在完整成功后原子发布，禁止覆盖已有检查点。

恢复前关闭公共入口、API 和所有写入进程，使用全新的隔离目标，并设置 `UNFREQ_RESTORE_ISOLATED=true` 后执行 restore。该变量只是操作者声明，不会自动隔离网络。损坏 gzip、非空目标和 SQL 错误必须失败，事务不得留下部分 SQL 写入。配置与媒体恢复步骤见[迁移说明](../server-migration.md)。

旧备份不知道备份后发生的撤回、删除、封禁和发布版本变化。恢复后必须通过可信的较新记录完成可见性同步，并验证未确认及已撤回内容不可公开，才可开放入口。没有该权威来源时继续隔离，不从旧备份推断作者同意。本轮恢复演练使用合成记录，不能给出生产 RTO/RPO 保证。

### 保留 C1 的回退

发生故障先隔离公共入口。只能成对切换到仍保留 C1 作者确认、撤回、白名单及版本检查的 API/Web，并保留 0024 和现有数据；不得运行自动公开历史内容或删除数据的补救操作。main `a5ebb9d` 已包含 C1 和 #23，可作为进一步验收的回退候选，不能据此宣称已完成目标环境回退。PostgreSQL 工作流中的 pre-C1 固定旧驱动任务只验证驱动兼容性，不证明公开服务的隐私安全回退。
